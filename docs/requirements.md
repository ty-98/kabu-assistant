# 要件 (要約)

全文: https://claude.ai/artifact/7uWrroHGS8L6D1gTK1L2Tj (2026-11-14 時点)

## 目的

「売買を当てる」ではなく「決めたルールを毎日自動で点検し、判断材料と記録を残す」。
防ぐのは3つ: 集中しすぎ、売買しすぎ、感情で動く。

## 分担

- データ取得と計算: GitHub Actions (Python)
- ニュース要約、解説、通知文: Claude のスケジュールタスク
- 保有の更新: 本人がスクショを Claude に送る

## 制約

- PayPay証券に個人向け公開APIなし。保有はスクショか手入力
- スプレッド: 国内株 立会時間内0.5% / 時間外1.0%、米国株 0.5〜0.7% + 為替コスト (要再確認)
- Claude のクラウド環境から株価サイトに接続不可。取得は GitHub Actions 側
- J-Quants 無料プランは12週間遅延。試作は無料の代替データ

## 機能と優先度

| 優先度 | 機能 | 状態 |
| --- | --- | --- |
| P0 | 保有台帳 | 実装済み (`data/holdings.csv`、`scripts/kabu/ledger.py`) |
| P0 | 日次の評価 | 実装済み (`scripts/kabu/report.py`) |
| P0 | ルール点検 | 実装済み (`scripts/kabu/rules.py`)。決算前ルールは決算カレンダー (P1) 待ち |
| P0 | アラート | JSON出力まで実装済み。通知はスケジュールタスク未設定 |
| P0 | 判断ログ | 書式のみ (`data/trades.csv`) |
| P1 | 日次ダイジェスト、決算カレンダー、知識カード、購入前チェック | 未着手 |
| P2 | 月次振り返り、候補抽出、ダッシュボード | 未着手 |

## フェーズと完了条件

| フェーズ | 完了条件 |
| --- | --- |
| 0. 準備 | 保有台帳の合計評価額が PayPay証券の画面と一致 |
| 1. 点検と通知 | 5営業日連続で自動実行され、誤った通知がない |
| 2. 情報と知識 | ダイジェストを1分以内で読め、全カードを本人が承認 |
| 3. 判断の規律 | その月の全売買に理由が記録されている |
| 4. 拡張 | フェーズ3を1か月使い、足りない機能を具体的に書き出せた場合のみ |

## 非機能

- 証券口座の認証情報を保存しない
- リポジトリは非公開
- 取得失敗の日は失敗と通知し、古い数字で判定しない
